# T2-3 匹配规则确认

日期：2026-10-04。以下前三项来自项目负责人在本阶段的明确答复。

1. **原名尾缀**：`行程单A↔发票A`、`行程单B↔发票B` 可以对应，`行程单A↔发票C` 无尾缀对应关系。金额缺失或差值超过 0.5，仍可通过明确原名关系匹配。
2. **金额层级**：优先选择按精度舍入后相等的候选；该层不唯一再核对原名。只有没有相等候选时才进入原始差值 ≤0.5 的候选层。
3. **一对一竞争**：同一行程单被多张发票竞争时，冲突相关发票均人工待核，其他独立匹配继续。

实现采用以下具体解释，并以用例验证，不新增模型字段：

- 数量按邮件全部发票/行程单计算，单对单例外仅在匹配开始时判断；不因过滤 b 类或已有匹配而再次触发。
- 多数量组合：先选相等候选层，否则选容差候选层；该层只有一项则拟配对，多项用尾缀在该层内消歧。两金额层均无候选时，允许用尾缀在邮件全部可用行程单中配对。若仍不唯一，人工待核。不选择“最近金额”，不使用最大匹配推断。
- 尾缀从完整解码原名去实际扩展名后，取最后一个对应角色词（发票/行程单）之后的文本。采用 Unicode NFKC、大小写统一、边缘空白/分隔符清理；保留尾缀内部字符。非空尾缀完全相等才形成名称候选；不模糊匹配、不按包含关系匹配，角色词之前的共同平台名称不作为证据。
- 名称不是唯一金额候选的额外否决条件；用户的 A/C 反例描述的是尾缀证据不成立。没有可识别角色词或尾缀为空时不猜名称关系，金额规则仍可工作。
- 所有拟配对先计算完毕再检查行程单占用；有竞争的全部撤回，不让附件遍历顺序决定获胜者。不通过排除已匹配项继续猜剩余关系。
- 持久化 itineraries 是行程单字段的事实来源；传入 DocumentResult 用于核对端口输入一致性。正式调用链中二者同时存在；不把提取结果临时复制成新的候选实体。
- 成功关系中的金额保留所选行程单的原始精度；金额/旅行字段缺失仍可按数量或名称规则建立关系，同时保留或补充实际异常待核。不将其他阶段待核状态改成 complete。
- 匹配阶段失败原因写既有 error_reason，并返回现有提示字典；不增加“匹配方法/置信度”字段。重复执行保持关系和原因稳定。
