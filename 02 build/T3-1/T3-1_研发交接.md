## 已做

- 页面调用 `run_pipeline` 后只读取 `stats.delivery_status`（`ready` / `summary_failed` / `package_failed`）、`delivery_zip_bytes` 和待核提示。只有 `ready` 且含现成 ZIP 字节时保存本轮下载对象；汇总表失败显示 P25 草案，包制作/核查失败显示 P26 草案，两者互斥。页面不调用 PDF 选择、命名或 ZIP 打包函数。
- 每次提交清掉上一轮下载对象。每轮以 `tempfile.mkdtemp` 创建独立临时目录，主流程返回的 ZIP 字节进入会话后清理处理目录。页面不提供桌面输出文件夹、模式切换或备份按钮；页面日志不展示内部路径。
- `mail_notice_cards` 根据后端 `mail_id`、文件序号、原名、结构化级别和原因按邮件归并：一封邮件一张提示卡，多项原因进详情。空主题/时间用明确占位，不新增发件人字段，不展示完整下载链接。P10 若后端同时给带 `code=P10` 的提醒和 mismatch，详情只保留一项。
- 完成提示优先取后端 `summary_row_count`，避免把 JSON 中未入表或去重跳过的记录算作汇总行数；缺该统计时不编造行数。
- 2026-10-26 按用户要求核查 IMAP 预设后，保留 163、QQ、126、Yeah 与手动输入；移除 Gmail 和 Outlook 预设。该筛选考虑当前程序实际使用 `IMAP4_SSL.login(账号, 授权码/密码)`，不把“有 IMAP 协议”误写为“当前登录方式必定可用”。
