# T3-6 研发交接（2026-10-26）

## 实现边界

`voucher_matcher.combine_vouchers(mail, results)` 只处理同一邮件已登记的文件级 `DocumentResult`。它不下载文件、不提取字段、不做发票↔行程单匹配、不进行跨邮件仲裁、不写 Excel/JSON，也不挑选交付 PDF。输入列表不被修改。

输出仍是 `DocumentResult` 列表：同票且可确认关系的来源合成一项，`source_file_seq` 保留原文件序号；关系或字段未决时保留独立候选。XML 优先仅用于带同文件位置证据且未自相冲突的字段；差异记录在 `conflicts`，并在 `error_reason` 标待核。无可靠 XML 值的字段冲突不做强行合并。

跨邮件同号、T2-4 仲裁、字段冲突后的 Excel 取舍由 T3-9 接入。T3-9 还需将 `field_evidence`、`conflicts` 写入最终 JSON，并在调用本模块前按 `file_seq` 保存 OFD/图片转换 PDF 路径，因为合并后的记录锚点可能是 XML。行程单的 `itinerary_identity_unconfirmed`/`itinerary_conflict` 必须阻止 T2-3 的“剩余一票一单”捷径；逻辑行程单的聚合来源也需写入 JSON。

## 规则与风险

- 仅同邮件判断跨格式同票。有效 20 位票号不同则分开；缺号来源只有在日期、价税合计、销售方三项有效且一致、唯一有号候选、且没有多份缺号来源争用时才合并。
- 多个 XML 自身字段冲突时不择一。无 XML 或 XML 缺可靠字段证据时，冲突候选独立保留并交后续仲裁。
- 同一行程单跨格式只在相同业务编号有来源位置证据、关键字段无冲突时自动合并。仅金额、时间、地点相似时保留并标待核。
- 旧 PDF 处理器可能只给扁平字段而无字段级证据。因此同号且字段一致可保守合并；冲突时本模块不选择来源，交 T2-4。真实处理器证据和端到端结果必须另测。
