# T3-3 XML 处理研发交接

状态：研发实现与自测完成；未做整链、独立测试或产品验收。现行解析器只支持已核对的 `EInvoice` 节点映射，未知模板返回 `Unknown` 和 `XML_UNSUPPORTED_TEMPLATE`，保留文件登记。

## 调用与证据

- 被测程序：`xml_processor.process_xml(CollectedFile, RunConfig, subject, mail_date, run_id)`。输出一份 `DocumentResult`，字段原值、规范值、来源 `file_seq` 和 XPath 存于 `field_evidence`。
- XML 发票号码同时读 `TaxSupervisionInfo/InvoiceNumber` 和 `Header/EIid`；两者冲突不任取其一。金额只取 `TotalTax-includedAmount`；销售方只取 `SellerName`；多项目票面类型不能唯一确定时留冲突。
- 大小、DTD/实体、节点数和深度有限制。解析器不联外、不自行生成 PDF、不决定跨格式同票，也不制造邮件主题或时间。

## 已运行

- `python -m unittest discover -s "02 build/T3-3" -p test_xml_processor.py -q`：7/7 通过。输入为研发事先写好的合成 XML，实际调用 `process_xml`；未替换解析器，检查字段、XPath、冲突和安全失败。该固定样本不是用户已审核的 18 条用例，也不是独立测试标准答案。
- 只读调用用户本机 `T3出行电子发票(XML)A.xml`，以规格中已核对的票号、日期、价税合计、票面类型和销售方作独立断言，全部相符；`field_evidence` 有六组字段。没有替换该 XML 原件，也没有运行邮件、跨格式、Excel、页面或 ZIP。
