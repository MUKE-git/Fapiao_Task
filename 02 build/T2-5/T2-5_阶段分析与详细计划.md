# T2-5 来源定位与命名约定

产品验收已全部通过。来源链为：邮件 UID → 本轮 Msg 编号 → 邮件内文件序号 → 实际内部文件 → 发票或行程单记录。实现与研发测试记录见 [研发交接](T2-5_研发交接.md)。

## 当前实现

- 按邮件搜索顺序分配 Msg 编号，mail_uid 独立保存 IMAP UID。邮件内保留文件统一编号；MD5 相同内容只保留首份，重复项记录原因。
- original_name 保存完整 MIME 解码原名；internal_name 清洗非法名称，完整长度最多 120 字符，计入前缀、扩展名及重名后缀，超长主体截断并加短摘要。实际扩展名保留。
- JSON 来源序号可反查邮件及内部文件；记录编号使用 mail_id-file_seq。导出业务名由 T3-8 填写，只有实际选中交付的来源才填 exported_name。
- 页面每轮创建独立临时目录，结果以 ZIP 下载，不提供桌面默认输出模式。

## 检查边界

匹配使用完整 original_name；仲裁复读来源文件使用内部名，不能互相替代。用户 Excel 只含八列业务字段，不包含完整来源链。来源字段存在和反查成功不证明票据真实或提取字段正确。

受控测试的输入、文件落盘和实际比较结果按原报告记录；不修改已审核用例编号、顺序、范围或预期。产品验收结论不等同于每个独立测试入口均已运行或通过。
