## 共享契约与唯一修改负责人

处理器逐文件返回 `DocumentResult(file_seq, role, fields, source_file_seq, error_reason, field_evidence, conflicts, pdf_path)`。`role` 只能是 `Invoice`、`Itinerary`、`Unknown`；证据逐项写 `file_seq/raw/normalized/location`，转换 PDF 路径指向本轮工作目录内已检查的副本。T3-6 只消费文件级结果并返回同票候选及证据；T3-9 在合并**之前**按原始 `file_seq` 保存各 OFD/图片的 `pdf_path`，以免 XML 成为记录锚点后丢掉转换件来源。`files[].exported_name` 只由 T3-8 选定交付 PDF 时填写。

本轮共享文件 `pipeline.py`、`data_model.py`、`stage_ports.py`、`processor_contracts.py`、`attachment_processor.py`、`config.py`，以及 T3 接入所需的 PDF 调用和本轮仲裁接线，由 T3-9 负责人统一修改。各研发独立工作树只改自己模块与测试：T3-2+T3-5 模型/图片、T3-3+T3-7 XML/链接、T3-4 OFD、T3-6 跨格式匹配、T3-8+T3-1 后端包/前端。两名测试工程师独立工作树，不修改生产代码或冻结库。`requirements.txt` 的 Pillow 由模型/图片负责人、reportlab 由 T3-9 统一补充。

接入顺序为：附件和正文链接统一登记、MD5 去重 → 按真实格式调用 PDF/XML/OFD/图片处理器 → T3-6 同邮件跨格式匹配 → T2-3 行程单匹配 → T2-4 本轮同号仲裁（跨邮件可靠 XML 优先）→ T2-6 字段校验、三关键字段全缺筛选 → 八列 Excel 与 JSON → T3-8 选 PDF、写导出名映射、核查精简 ZIP → T3-1 只展示结果状态和下载按钮。T2 原有欠项仍归 T2。
