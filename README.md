# 发票邮件处理

给通过邮件接收发票和行程单、需要整理个人报销材料的人使用。以往要逐封打开邮件、下载票据、抄录字段，再核对发票和行程单的对应关系。现在可以在一个页面发起批量处理，下载本轮汇总表和票据 PDF，并按提示回原邮件核对有疑问的记录。

## 你会拿到什么

下图展示发票信息汇总表的八列布局。

![发票信息汇总表示例，展示八列报销字段](01%20docs/assets/summary-preview.png)

处理完成后，点击页面的 **下载本轮结果**。下面的 ZIP 示例使用截图中的示例日期和金额构造票据文件名。`用户票据/` 内共有 7 个 PDF，包含三组 a 类发票与行程单，以及一张 b 类发票。实际票据数量取决于本轮可交付的文件。

```text
fapiao_YYYYMMDD_HHMMSS.zip
└── Invoice_Task/
    ├── 发票信息汇总表.xlsx
    ├── task_debug.json
    └── 用户票据/
        ├── 客运服务费+2026-09-12+86.52元.pdf
        ├── 行程单+2026-09-12+86.52元.pdf
        ├── 代收通行费+2026-09-17+12.6元.pdf
        ├── 行程单+2026-09-17+12.6元.pdf
        ├── 客运服务费+2026-09-23+112.35元.pdf
        ├── 行程单+2026-09-23+112.35元.pdf
        └── 配送服务费+2026-09-22+35.8元.pdf
```

| 结果 | 用途 |
|---|---|
| 汇总表 | 按发票逐笔列出发票日期、发票号码、报销金额、发票类型、票面类型、出行时间、销售方、出发地/目的地。已匹配的交通类发票可汇入行程信息 |
| 票据 PDF | 用业务名整理可交付的发票和行程单，方便核对及归档。有可用的原始 PDF 时优先交付其副本，符合条件的图片可转成 PDF |
| `task_debug.json` | 从记录反查来源邮件、文件及处理原因。页面提示可帮助定位待核项，详细字段与来源可结合 JSON 和原件核查 |

## 快速开始

1. 在邮箱中开启 IMAP，准备账号和授权码，将需要处理的目标邮件保留为未读。
2. 在项目根目录安装依赖。

   ```powershell
   python -m pip install -r requirements.txt
   ```

3. 按下方配置说明填写百炼 API Key、文本模型和图片模型。
4. 启动页面，在表单里选择邮箱服务器并填写账号和授权码。支持 163、QQ、126、Yeah 预设，也可手动输入 IMAP 地址。

   ```powershell
   python -m streamlit run app_demo.py
   ```

5. 点击 **开始处理**。处理结束后查看待核提示，点击 **下载本轮结果**，结合原邮件核对汇总表和票据。

### 模型配置

在项目根目录的 `.streamlit/secrets.toml` 中选择下面一组配置，也可使用同名环境变量。型号仅作配置示例，实际可用性取决于账号权限、地域和服务支持。

**千问（方案 C）**

```toml
DASHSCOPE_API_KEY = "填写百炼 API Key"
DASHSCOPE_MODEL = "qwen3.7-max"
DASHSCOPE_VISION_MODEL = "qwen3-vl-plus"
```

**DeepSeek（方案 A）**

```toml
DASHSCOPE_API_KEY = "填写百炼 API Key"
DASHSCOPE_MODEL = "deepseek-v4.1-flash"
DASHSCOPE_VISION_MODEL = "deepseek-v4.1-flash-1017"
DEEPSEEK_BASE_URL = "https://实际业务空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
```

方案 A 的地址须替换为自己的百炼业务空间及地域对应的兼容接口地址。文本和图片模型须属于同一个已接入的家族，型号可以不同。API Key 优先读取环境变量，模型名称优先读取 `secrets.toml`。请将真实密钥留在本地配置中。接入与验证细节见 [A 接入说明](A_接入验证说明.md)和 [C 接入说明](C_接入验证说明.md)。

## 处理范围与限制

- **取件。** 筛选收件箱中主题符合发票相关关键词的未读邮件。存在非 OFD 附件时只处理附件，否则检查正文下载链接。普通 ZIP 本身算附件，带文件名的内嵌部件也可能算附件。OFD 直接忽略。
- **识别与配对。** 逐文件处理 PDF、XML 和图片。发票逐笔汇总，行程单按一对一规则匹配。字段缺失、冲突或关系不确定时，系统给出核查提示。仅有 XML 时可以保留业务记录，并提示缺少可交付的票面 PDF。
- **复核与重复运行。** 产品用于整理材料，真伪查验和报销审批仍由用户所在流程处理。程序不会自动标记邮件已读，同一批未读邮件再次运行可能重复输出。
- **已知限制。** 附件名含“发票”而实际内容无关时曾出现报错，该场景暂不修复。请按提示核对原件。

## 验收与验证

产品验收已全部通过，用户反馈整理效率有所提升。现有资料没有同一批材料的人工与自动耗时对照，因此暂以定性反馈记录效果。

- **业务预期。** 18 条必选虚构用例的原有预期已人工审核，逐字段扩展预期仍待人工审核。见[固定用例库](03%20tests/owner%20test/固定用例库/README.md)和[逐字段扩展草案](03%20tests/T3/冻结18条逐字段扩展_测试工程师草案.md)。
- **运行证据。** 受控整链测试和真实模型请求分别记录，覆盖条件和观察结果见[T3 集成与测试交接](02%20build/T3-9/T3-9_集成与测试交接.md)及上方 A、C 接入说明。真实请求使用的样本及字段差异以各次记录为准。
