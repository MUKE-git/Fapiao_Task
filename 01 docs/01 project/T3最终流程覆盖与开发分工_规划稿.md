# T3 最终流程覆盖与开发分工（规划稿）

日期：2026-10-13，职责边界于 2026-10-21 修订。规划前提：**假定 T2 已开发完成且测试通过**，据此设计 T3；这是假设，不代表 T2 当前代码或独立验收实际完成。T3 计划与 T2 开发并行。依据为《重构方案》§2 最终目标图、§3～8 和《计划分工》阶段三。T3-1～T3-7 原编号不变；T3-8、T3-9 分别承接从前端和匹配任务中拆出的后端工作。

## 上次判断的更正

我先前写“启动 T3 实现须核对 T2 对应接口与交接基线”，容易让人认为 T3 材料要等 T2 完成。正确做法是**现在形成 T3 全套开发计划**；以后联调时由技术负责人核对实际代码。现有计划已写明 T3-1、T3-2、XML、OFD、跨格式凭证匹配、正文链接，重构方案还写明图片。仍需补的是开发细节和逐分支覆盖，而不是重新决定这些任务是否属于 T3。

## 最终图逐分支核对

图中一个判定箭头不代表可以忽略同封邮件里的其他文件。**XML+OFD、XML+PDF+OFD、链接+直接附件**均要登记全部文件并尝试同票合并。ZIP 和链接是获取途径，不是文件类型。跨格式凭证匹配与发票↔行程单匹配是不同环节。

## 分工与交接

| 工作流 | 开发交付 | 联调对象 |
|---|---|---|
| T3-1 前端 | 页面提示、按邮件归并、原邮件定位、已核查 ZIP 下载按钮；移除本机桌面模式控件 | T3-9 状态、T3-8 产物 |
| T3-2 模型接入 | 供应商/模型配置、文本与多模态适配、逐文件结果校验、重试及受控并发 | PDF、图片、二次仲裁 |
| T3-3 XML | 安全解析、字段映射、仅 XML 和异常 | T3-6 |
| T3-4 OFD | 字段提取、PDF 转换、损坏/加密异常 | T3-6 |
| T3-5 图片 | 图片发票/行程单识别、本地硬规则、异常 | T3-2、T3-6 |
| T3-6 跨格式凭证匹配 | XML/OFD/PDF/图片同票关系、字段补全/冲突、落单回流、来源合并；只返回候选和证据 | 各格式处理器、T3-9 |
| T3-7 正文链接获取 | 链接发现、限定下载、失败记录，结果送公共附件链 | 附件处理、T3-6 |
| T3-8 后端交付包 | 可用 PDF 选择、交付业务名、`exported_name` 映射、精简 ZIP 生成和完整性核查 | T3-4/T3-5 转换件、T3-9 最终结果 |
| T3-9 主流程接入 | T3 各入口/处理器和 T3-6 结果接入 T2 匹配/仲裁/校验、Excel/JSON 与 T3-8；本轮工作目录和失败状态 | 公共附件链、T2 各模块、T3-1/T3-8 |

**T2 基线不改归 T3。** PDF 逐文件处理、直接附件/ZIP 的 MD5 与编号、既有发票↔行程单匹配、本轮 PDF 同号仲裁、字段校验和八列 Excel/JSON 仍由 T2 原任务完成并交接。T3-9 只接入 T3 新格式与链接、XML 优先等增量；T3-8 核对并扩展现有后端交付能力，尤其是多格式来源和精简 ZIP，不重做 T2 业务规则。若 T2 基线仍有未完成项，由对应 T2 任务收尾，不把欠账改名塞进 T3。

`stage_ports.py` 已留 `process_xml`、`process_ofd`、`process_image`、`combine_vouchers` 接入点，`DocumentResult` 是最小文件级结果。链接来源、多文件合并和一文件多票等契约增量由技术负责人设计，保持已有公开接口兼容，并让主流程、JSON、测试一并更新；接口细节不交产品负责人裁决。前端不新增发件人字段。

格式处理器、模型接口和链接入口可在共同结果契约下并行；T3-6 在文件级结果上判断同票，T3-9 接入统一主流程，T3-8 生成交付包，T3-1 展示并提供下载。这只细化 T3 内部依赖，不改 T1→T2→T3 主线。T2-3 的非阻断衍生项可排在主图所有节点完成之后；已批准的 T2-3 规则仍保留。

## 开工前交付材料与决策归属

1. 技术负责人出**格式字段映射表**：XML 节点、OFD 结构/页面、PDF 文本、图片识别值如何映到 JSON 与八列；XML 有效值优先、其他凭证补空、冲突显式待核，并列异常。
2. 技术负责人出**配对决策表及接口样例**：同票、异票、缺票号、一对多、多对一、同票字段冲突、落单回流及来源证据。
3. 技术负责人出**链接获取与安全规则**：重定向、超时、大小、类型、去重、失败；页面/日志不暴露含签名的完整下载 URL。
4. T3-1 出**单独的前端提示文案表**供产品审核。每条待核项显示现有邮件主题、邮件时间及有关文件；不新增发件人字段。

独立验收属于测试侧，不列入上述研发分工。测试工程师的草案放 `03 tests/T3/`；现有 18 条必选用例已由用户审核，不改编号、顺序和预期；新增/加工标明“测试工程师制作，待用户审核”。

产品负责人只需审核用户可见行为和业务取舍，尤其是前端文案、缺凭证/冲突时的显示与处理；处理器签名、序列化、模型适配由技术负责人负责。文案见《T3前端提示文案表_待产品审核.md》。
