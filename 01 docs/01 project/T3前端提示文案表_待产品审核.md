# T3 前端提示文案表（待产品审核）

日期：2026-10-13。用途：请产品负责人审核**语言是否准确、清楚、得体，以及用户动作是否合适**。此表是产品文案草案，不代表前端代码已实现；触发条件由研发按《重构方案》最终流程接线。页面避免用“您操作错误”“假发票”“校验通过”等会误导或冒犯的说法；本系统不做发票真伪校验。

## 每条待核结果的固定定位区

对每封有待核事项的邮件显示以下现有信息，用户可据此回到邮箱找原件：

| 页面标签 | 内容与缺失处理 |
|---|---|
| 邮件主题 | 完整解码主题；空值显示“（无主题）”。页面可折行，允许复制全文。 |
| 邮件时间 | 使用现有邮件日期字段，显示 `YYYY-MM-DD HH:mm`；无法取得时显示“（邮件时间不可用）”。不能以处理时间冒充邮件时间。 |
| 相关文件 | 文件原名及本轮文件编号；多个来源逐个列出。用户可按邮件主题和邮件时间定位，再核对附件。 |

现有 `mail_uid` 保留为内部追源锚点，不要求用户在网页邮箱输入 UID。本阶段不新增发件人字段。下载链接若含签名/令牌，页面只显示链接所在邮件和下载结果，不展示完整链接参数。

同一邮件可有多条原因，但页面以**邮件卡片 → 具体发票/文件 → 原因**组织，避免反复显示相同主题。某字段从 XML 等来源提取成功但尚未做真伪校验时，页面只说“已提取”，不说“已验证”。页面不声称用户能在下载包内找到未交付的原格式文件；需查看原件时引导用户到原邮件。

### P07～P10、P26 的触发边界

- **P07 XML**：字节不完整或 XML 语法不成立属于文件本身异常；XML 可正常打开但缺少项目需要的节点，也可能只是模板不同或字段确实未填，不能说文件“坏了”。仅缺部分字段时保留已取得的值。
- **P08 OFD**：OFD 容器损坏、加密或结构不受当前工具支持会妨碍解析；字段已提取但转换 PDF 的工具报错，是转换环节失败，不等于 OFD 文件错误。提示只指出实际失败的环节。
- **P09 图片**：图片可打开但模糊、遮挡、票面不完整或识别结果缺字段时触发；图片字节打不开归 P06，模型服务不可用归 P22。不能一概归因于用户拍摄质量。
- **P10 凭证类别**：比较的是 **Invoice 发票 / Itinerary 行程单 / Unknown 无法判断**，不是 PDF/XML/OFD 等物理格式。当前 PDF 链先从附件原名关键词推断（“行程单”优先于“发票”），再从 PDF 正文关键词粗分；原名有明确关键词时优先形成本机预读类型，AI 的 `file_classifications` 逐文件给出另一份分类。例如原名为“行程单.pdf”、正文及 AI 均判断为发票，就会出现分歧。当前旧逻辑还把正文的 `Unknown` 当作比较值，因此“原名能判断、正文无法判断”也可能触发提示；这不能称为两个明确判断相反。T3-1/T3-2 联调应把“无法判断”和“明确相反”分开显示，同一文件只给一次 P10 提示，详情列出实际参加判断的依据。
- **P25/P26 先后关系**：汇总表未生成时显示 P25，停止进入打包流程；汇总表已生成，随后制作 ZIP 或核对包内 Excel、JSON、应交付 PDF 失败时显示 P26。同一失败不同时显示两条。
- **P26 下载包**：当前页面在调用 `st.download_button` **之前**生成 ZIP；点击按钮只是取已生成的数据。当前代码尚未实现 P26 的专门捕获与完整性检查，打包函数还可能跳过读不到的文件。T3-1 应在展示按钮前检查包是否生成且所需文件齐全。若打包失败，当轮结果页直接显示 P26 且不展示下载按钮；用户尚未点击下载，所以不写“重试下载”。浏览器点击后的传输失败是另一种情况，不能冒充 P26 的触发条件。本机和云端运行均使用同一下载行为。
