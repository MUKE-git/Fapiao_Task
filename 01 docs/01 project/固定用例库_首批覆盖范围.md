# 发票处理固定用例库：首批覆盖范围

本文件是用例库建设的第 1 步：确定需要收集和审核哪些材料。多数用例以**一封邮件及其原始附件**为固定输入；「无未读邮件」以邮箱状态快照为空为输入。同一封邮件中的发票、行程单和 ZIP 不拆开，以便验证邮件筛选、附件关系、字段提取和最终输出。

18 条必选场景的合成固定材料与逐条审核入口见[固定用例库](../../03%20tests/owner%20test/固定用例库/README.md)。场景编号与范围暂时冻结，全部标准答案仍待人工审核。

## 首批目标

- 在 4 天内形成一批可逐条审核、可重复运行的固定用例。首批覆盖下表 **18 个必选场景**；C10、C20、C21 为可选。各必选场景至少由一条**已审核**用例覆盖。
- 每条用例都能回答：该邮件是否应处理、哪些附件应被读取、每个 PDF 是什么类型、应得到哪些字段、应生成几行汇总表、哪些文件需要人工核查。
- 用例的人工标准答案与每次运行结果分开保存。AI 的一次输出不能自动成为标准答案。
- 各场景写明前置状态、预期输出、异常结果、副作用和可复现证据；测试一个环节时，上游依赖须处于已知可用状态，避免前置错误导致误判。
- 同一份固定邮件材料可用于多个环节检查；切换已读/未读等输入状态时，分别记录为独立变体。

## 场景清单：按主流程顺序

| 编号 | 优先级 | 场景 | 选样要求 | 审核重点 |
| --- | --- | --- | --- | --- |
| C01 | 必选 | 无未读邮件 | `INBOX` 的 `UNSEEN` 结果为空 | `unseen_total=0`；无附件下载、AI 调用和新增汇总行 |
| C02 | 必选 | 主题不命中 | 未读邮件主题无发票/报销相关关键词，即使有 PDF | 整封跳过，不生成汇总行或附件输出 |
| C03 | 必选 | 命中主题但无 PDF | 主题命中，附件为空或只有非 PDF 文件 | 不生成汇总行，记录无 PDF 情况 |
| C04 | 必选 | 普通发票 | 主题命中关键词，直接附一张文字可提取的 PDF | 日期、号码、价税合计、发票类型、票面类型、销售方；汇总表 1 行 |
| C05 | 必选 | 单张发票与单份行程单同封 | 各一份 PDF，可明确对应 | 附件角色、出行时间、出发地/目的地；验证这一组 1:1 的结果，不代表多对一匹配已通过 |
| C06 | 必选 | ZIP 根目录 PDF | ZIP 根目录有发票 PDF | 解压、原始文件名、提取字段与重命名 |
| C07 | 必选 | 多附件及重复文件 | 同封邮件有多个附件，至少一份 PDF 在直接附件和 ZIP 中重复 | 按内容去重，最终保留的 PDF 数量 |
| C08 | 必选 | 无类型提示的附件名 | 原名不含发票/行程单关键词，正文可判断 | 类型判断依据与最终文件名 |
| C09 | 必选 | 扫描件或不可读 PDF | PDF 文本为空或读取失败 | 明确缺失/失败状态，不把猜测值作为标准答案 |
| C10 | 可选 | 附件名与正文类型冲突 | 原名提示发票，正文提示行程单，或反向 | 最终类型、冲突提示和「待人工核查」后缀 |
| C11 | 必选 | 金额或日期有歧义 | 同一 PDF 有单价、税额、价税合计，或同时有开票和出行日期 | 金额取价税合计；两种日期不混用 |
| C12 | 必选 | 关键字段缺失 | 发票 PDF 缺少或无法识别号码、日期、金额中的一项或两项；另设三项全缺变体 | 各缺失项标记并保留核查原因；只缺一项或两项仍生成汇总行，三项全缺才不入汇总表；两种情况都在 JSON 保留发票记录 |
| C13 | 必选 | 交通类发票无行程单 | 一张关键发票字段齐全的交通类 a 类发票，同封邮件没有行程单 | 发票记录及汇总行保留；`matched_itinerary` 为空，不汇入旅行字段；产生能定位到该邮件和发票的缺行程单待核提示 |
| C14 | 必选 | T2-3 金额层级 | 一张 a 类发票金额 100.00；同封行程单分别为 100.0000、100.40 | 优先配 100.0000（按精度舍入后相等层）；100.40 虽在容差内也不能抢先，未匹配行程单仍保留，匹配金额保持原精度 |
| C15 | 必选 | T2-3 同层原名消歧 | 发票 B 与行程单 A/B 的金额均处同一优先层，原名尾缀分别为 B/A/B | 金额层有两候选时用完整解码原名尾缀选行程单 B；A 保留为未匹配，内部重命名不影响结果 |
| C16 | 必选 | T2-3 容差边界与下一步原名 | 每个变体均有至少两份行程单以避开单对单例外；发票金额 100.00，目标行程单差值分别为 0.49、0.50、0.51，另有明显不匹配的干扰项；0.51 再分别设原名尾缀相同/不同 | 无相等候选时，0.49、0.50 属容差候选；0.51 不属金额候选，但仍须继续检查原名：尾缀唯一相同则成组，不同且无其他证据才待核；不得仅因超 0.5 直接拒绝 |
| C17 | 必选 | T2-3 原名兜底 | 多数量组合，发票 A 的金额缺失，行程单 A/B 金额各异，只有 A 的原名尾缀对应 | 发票 A 与行程单 A 成组；发票金额继续标缺失并待核，不由行程单金额代填；B 保留为未匹配 |
| C18 | 必选 | T2-3 多票竞争一单 | 两张 a 类发票均拟配同一份行程单，另有第三张发票与另一份行程单独立对应 | 两张竞争票均无 `matched_itinerary` 并人工待核；第三张仍成功配对；被争用的行程单保留，不按发票遍历顺序决定赢家 |
| C19 | 必选 | T2-3 无法匹配或无法唯一确定 | 一张 a 类发票面对多份行程单：金额候选不唯一且原名无法消歧；另设无金额候选、尾缀 A/C 不对应的变体 | 无唯一证据时不按最近金额或附件顺序猜测；该发票无 `matched_itinerary` 并待核，全部未匹配行程单保留在 JSON |
| C20 | 可选 | T3 后续优化：末尾单对单 | 同邮件两张 a 类发票、两份行程单：第一张按金额和原名都找不到；第二张能唯一匹配其中一份，最后各剩一张发票和一份行程单 | 第一张失败不终止处理，第二张先成功；随后剩余一票一单自动成组，即使这两份原先没有金额或原名对应证据；两组关系各指向自己的来源文件 |
| C21 | 可选 | T3 后续优化：多个剩余项 | 同邮件三张 a 类发票、三份行程单：一组有唯一证据，另外两张发票与两份行程单均无可确定关系 | 唯一的一组成功；剩余多张票、多份单均人工待核，不按附件顺序、最近金额或“排除已配对项”逐个猜关系；全部候选保留 |

> C01–C11 保持原有场景和顺序；C12、C13 仅按要求修正预期与审核证据；C14–C19 细化审核重点；C20、C21 作为 T3 后续优化的可选用例保留，不计入当前 T2 验收。C05 已覆盖初始单票单行程单，C13 已覆盖无行程单，不另造重复场景。

> **待同步的规则差异**：C20 的末尾单对单自动成组已移至 T3 后续优化。现行《重构方案》§4.2 与 `T2-3_匹配规则确认.md` 明确规定单对单例外只按同邮件初始总数判断，匹配后不再次触发；当前匹配器也按初始总数处理。C20、C21 均为可选，不作为当前 T2-3 完成条件；后续若启用 C20，需先更新业务规则与实现。C16 的 0.51 通过唯一原名尾缀兜底符合两份文档的 2026-10-04 细化规则。

本批 18 条必选场景均允许用**明确标记的合成材料或邮箱状态快照**制作；C10、C20、C21 暂不制作，不影响首批完成。不得将合成样本标为真实邮件。网络故障、邮箱登录失败、API Key 错误及 Excel 文件占用属于运行环境故障，首批先记录，不作为固定邮件用例的入库门槛。

## 每条材料的入库门槛

1. 保存可重放的原始输入：一般为邮件主题、Date 头、附件原名和原始 PDF/ZIP，并记录每个附件的 SHA-256；C01 记录空邮箱状态。邮件序号、桌面路径和重命名后的文件名不是原始输入。
2. 真实邮件先脱敏。脱敏后若无法人工判断号码、金额等标准答案，应保留安全的私有原件供审核，或放弃该样本；不能凭运行输出补猜。
3. 人工填写或修正标准答案，并给关键字段标注 PDF 页码、可定位的文字或邮箱状态依据。无法判定的字段明确标为“不确定”，不强行判对。
4. 审核结论为“通过”后才计入上表覆盖率；“待审”“退回”“暂缓”都不计入。

## 审核时统一核对的输出

- 邮件层：应处理/跳过、预期 PDF 数量、预期汇总行数。
- 附件层：每个 PDF 的真实角色（发票、行程单、其他）、是否重复、是否应标记人工核查。
- 字段层：`invoice_date`、`invoice_number`、`total_amount`、`invoice_type`、`receipt_type`、`seller`、`travel_time`、`origin_dest`。无值与不适用分别记录。
- 文件层：预期文件类型及命名要素；运行批次造成的 `Msg` 编号、同名避让序号和输出目录不参与标准答案比较。
