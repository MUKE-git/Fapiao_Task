# T3-1 前端页面规格（待产品审核）

2026-10-21 按产品要求明确边界：**T3-1 只负责前端页面**。本稿只规定用户看见什么、如何定位原邮件、何时能点击下载。用户交付包的内容与命名属于产品需求；OFD/图片转 PDF 分别由 T3-4/T3-5 实现，PDF 选择、业务命名、JSON 映射、ZIP 生成和完整性检查由 T3-8 实现，跨格式结果如何进入整条流程由 T3-9 负责。本稿不把这些后端工作交给前端工程师。

## 页面显示

- 页面读取后端已经生成的本轮结果和待核原因，按**邮件**归并提示：一封邮件只显示一条邮件级提示，文件或字段原因放在详情里。邮件主题、可用的邮件时间、相关文件原名与本轮编号帮助用户回邮箱找原件；不新增发件人字段。具体措辞与编号见《T3前端提示文案表_待产品审核.md》P01～P26。
- 区分信息、提醒、错误；缺字段、有值但格式错误、缺凭证、同号冲突、文件打不开、链接失败等按后端的结构化原因显示。前端不得靠文件名、扩展名或提示文字自行重新判断业务状态，也不得把技术登记信息当成必然需要用户核对的事项。
- 页面可展示已确认的记录和待核细节；不声称系统完成发票真伪或签章验证。用户不能在交付包里找到的 XML/OFD/图片原件，应提示其回原邮件查看。

## 下载控件

| 后端返回的本轮状态 | T3-1 页面行为 |
|---|---|
| 已生成并核查交付 ZIP | 显示“下载本轮结果”，按钮只提供该现成 ZIP；本机或云端运行的页面行为相同。 |
| 汇总表未生成 | 显示 P25，不显示下载按钮。 |
| 汇总表已生成，但交付 ZIP 生成或完整性检查失败 | 显示 P26，不显示下载按钮，不同时显示 P25。 |
| 用户点击后浏览器传输失败 | 若页面仍保有已生成 ZIP，允许再次点击按钮；不把传输失败冒充 P26。 |

页面删除桌面输出文件夹输入、模式切换和“下载备份”入口，不显示内部工作目录。按钮出现以前的文件制作、目录隔离、临时目录生命周期和检查责任归 T3-8/T3-9；前端只消费明确的成功/失败状态。具体交付内容及命名见《T3-8_用户交付包生成规格_研发稿.md》。

## T3-1 验收边界

核对 P01～P26 的触发显示、按邮件归并、邮件主题/时间/文件定位、详情展开、P25/P26 互斥、下载按钮可见性及取消本机模式的页面控件。可用受控后端结果先核对页面，再以真实 T3-9/T3-8 输出联调。页面测试通过不能证明 XML/OFD/图片提取、业务名或 ZIP 内容正确；这些由各自任务和独立测试核查。
