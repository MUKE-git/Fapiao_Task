# T3-1 用户导出与下载规格（待产品审核）

日期：2026-10-13。范围为《计划分工》T3-1 的用户交付包和下载行为；前端提示另见《T3前端提示文案表_待产品审核.md》。T2 按已完成且测试通过作为 T3 规划前提，不代表当前代码实际状态。本稿按产品最新意见修订：用户交付的票据仅限发票和行程单 PDF，处理用原件及内部目录不进入交付包；取消本机桌面输出模式，统一下载 ZIP。“申请单”经产品确认指现有流程的“行程单”，本稿统一使用“行程单”。

## 1. 用户收到什么

- **用户 Excel**：`发票信息汇总表.xlsx`，仅八列，按现有规则逐笔追加**本轮**记录；每轮新建工作目录和汇总表，不向历史运行的表格追加。行程单不另占一行。JSON 金额保留十进制原精度，Excel 显示两位。
- **调试文件**：`task_debug.json`，保留邮件、文件、发票记录、全部行程单和来源信息，供追溯与核查。
- **用户票据**：只放实际可交付的发票 PDF 与行程单 PDF。XML、OFD、图片可以是识别输入或 PDF 转换来源，但原格式不交付；未知角色文件不放入用户票据。
- **内部处理文件**：继续用 `Msg{邮件序号}_{文件序号}_{安全名}` 登记和处理。内部目录与用户交付目录隔离；`1_Downloaded_Zips/`、`2_Extracted_PDFs/`、原始邮件 ZIP、过程文件及日志均不进入用户 ZIP。
- **统一下载**：无论程序在本机还是云端运行，每轮都在独立临时工作目录处理，只通过页面下载精简 ZIP。页面不提供桌面输出文件夹、模式切换或“下载备份”入口。工作文件与待下载交付目录隔离，打包后按既定规则清理临时工作文件。

## 2. 票据 PDF 的选择与业务文件名

同一张发票可能同时有 XML、PDF、OFD 等来源，先按 T3-6 规则形成同一业务记录，再选择交付凭证；不得把每种来源格式各导出一份。行程单按其自身记录选择 PDF。两份 PDF 即使字节不同，只要票号等关键业务信息一致且均通过凭证检查，就属于同票的重复来源，交付一份即可：优先原始 PDF；同优先级时按文件登记顺序选首份，其余来源仍留在 JSON。**同号但金额、日期等关键字段冲突**属于另一种情况：先按 XML 优先及本轮仲裁规则确认业务记录；仍无法确认时，不随意选 PDF 交付，保留冲突来源和前端待核提示。

| 场景 | 用户票据中的结果 |
|---|---|
| 已有可用的原始 PDF | 交付该 PDF 的业务名副本；PDF 优先于同票 OFD/图片转换件。 |
| 无原始 PDF，但有可用 OFD | 将 OFD 转换成 PDF，经转换结果检查后交付；不交付 OFD。 |
| 无原始 PDF/OFD，但有可用票据图片 | 将图片转换或排版成 PDF，经结果检查后交付；不交付图片。 |
| 只有 XML 发票 | 保留结构化发票记录并标“缺凭证”，不凭空生成票面 PDF；`用户票据/` 无该发票文件。 |
| 转换失败、角色无法确认或业务值冲突且凭证无法唯一选择 | 不交付未经确认的 PDF；JSON 记录原因，页面给出对应待核提示。其他已确认票据继续交付。 |

优先级只在**已成功生成且通过检查**的候选 PDF 中比较：OFD 转换失败而同票图片可用时，可继续用图片形成交付 PDF。原始 PDF、转换后的 PDF 均应确认文件可读取且内容与选定来源对应；改扩展名不能代替转换。OFD/图片转 PDF 只改变交付形态，不改变原来源格式、提取结果和匹配证据。链接下载得到的 PDF 按同一规则处理。

| 交付角色 | 文件名模板 | 取值来源 |
|---|---|---|
| 发票 PDF | `{票面类型}+{开票日期}+{金额}元.pdf` | 优先取**选中凭证自身**已确认的票面类型、日期和价税合计；该凭证无值时只用对应缺失占位，不从另一来源暗中借值。 |
| 行程单 PDF | `行程单+{出行日期}+{金额}元.pdf` | 取**选中行程单自身**的首笔出行日期和匹配金额，不借发票日期或金额。 |

### 日期、金额、票面类型的文字处理

1. 日期在有值且有效时统一用 `YYYY-MM-DD`。行程单取首笔行程日期；发票取开票日期。
2. 金额用十进制文本，保留该文件有效输入的小数位（最多四位），不先用二进制 `float` 或固定两位四舍五入。**Excel 显示两位不改变 JSON 或文件名的金额原精度**。金额文本不带 `¥`、逗号或空格。
3. 票面类型按既有 `*一级*二级` 规则取二级并清理存盘禁用字符。不能从另一文件的票面类型补这个文件的导出名。
4. 缺日期用 `日期缺失`，缺金额用 `金额缺失`，缺票面类型用 `票面类型缺失`。**金额缺失后不加“元”**：例如 `票面类型缺失+日期缺失+金额缺失.pdf`；有金额时才是 `...+121.74元.pdf`。占位仅用于文件名，不改 JSON 的业务值。字段有值但格式错误时也不得把错误文本写入文件名，应使用相应占位并提示具体错误。

### 文件名安全和 JSON 映射

- 导出扩展名一律 `.pdf`。清理路径分隔符、控制字符和 Windows 非法文件名字符；不得写出 `用户票据/`。完整解码原名仍保留在 JSON。
- 同名交付 PDF 按文件登记顺序加 `(1)`、`(2)` 避免覆盖，按大小写不敏感比较。扩展名和重名后缀都计入完整名称最多 120 字符。
- 超长时只截断业务名主体并加短摘要，保留扩展名和重名后缀；摘要由该文件稳定信息计算，确保同一文件重复计算得到同名。先预留后缀长度，再裁剪，最终完整文件名不超过 120 字符。
- `files[].exported_name` 仅在该来源被选中并实际交付 PDF 时填写对应业务文件名。未选中的 XML/OFD/图片、重复来源、未知文件和仅 XML 的来源保持空值；不能把同一交付 PDF 冒记为每个来源各交付一次。若从 OFD/图片转换，选中的原来源文件条目填写所生成的 PDF 名称，`original_name`、`internal_name` 保持原义。
- `internal_name` 是处理时的内部存盘名，**不表示该文件存在于交付 ZIP 中**。JSON 保留原邮件定位、原文件名、文件序号和导出名，不能让用户误以为内部路径可在 ZIP 内打开。

## 3. 下载 ZIP 内容

```text
fapiao_时间戳.zip
└─ Invoice_Task/
   ├─ 发票信息汇总表.xlsx
   ├─ task_debug.json
   └─ 用户票据/
      ├─ 客运服务费+2026-04-27+121.74元.pdf
      └─ 行程单+2026-04-27+121.74元.pdf
```

示例只表示包内结构和命名，不表示给定 A 组样本存在行程单。若本轮没有可交付 PDF，可不创建 `用户票据/`；Excel 与 JSON 仍按主流程生成，并显示相应缺凭证/待核提示。不把整个临时工作目录直接打包。

生成顺序：先确定应交付的 PDF 并完成转换、检查、业务命名，再填写相应 `files[].exported_name`，然后序列化最终 `task_debug.json`，最后构建 ZIP。ZIP 完成后逐项核对 Excel、JSON、每份应交付 PDF 和包内清单；同时确认包内未出现 XML、OFD、图片、原始 ZIP、内部目录或日志。不以“ZIP 字节非空”代替完整性检查。

## 4. 页面下载行为及失败边界

| 场景 | 页面行为 |
|---|---|
| 处理成功（本机或云端运行） | 显示“下载本轮结果”；ZIP 已在按钮出现前生成并通过内容检查，临时工作文件按既定清理规则处理。 |
| 汇总表未生成 | 显示 P25，不进入 ZIP 制作，不显示下载按钮。 |
| 汇总表已生成，随后打包或完整性检查失败 | **P26 在点击下载之前直接显示**，不显示下载按钮，说明本轮无法下载并引导重新运行；不同时显示 P25，也不指向本机输出目录。 |
| 用户点击按钮后浏览器传输失败 | 不属于 P26 的打包失败；服务器已生成 ZIP。若页面仍在，可再次点击现有按钮。前端不声称能检测所有浏览器端保存失败。 |

当前 `app_demo.py` 仍有本机桌面输出、文件夹名输入、模式判断和“ZIP 备份”提示；已在 `st.download_button` 前调用 `zip_directory_to_bytes`，但尚无 P26 专门错误处理。`utils.py::zip_directory_to_bytes` 可能跳过读不到的文件，当前代码还把整个输出目录直接打包，尚未建立独立交付目录。T3-1 需使页面始终提供临时工作根目录；`config.py::RunConfig` 在未提供 `output_root` 时仍默认写桌面，研发需防止其他入口意外触发这一旧行为。`pipeline.py` 目前只使用配置给出的路径，没有本机/云端分支；仅取消模式本身不要求改其业务处理逻辑。`utils.py::format_amount_text` 当前经过 `float` 并格式化至两位，不适合作为保留最多四位原精度的导出名金额。以上为 T3-1 实施目标，不是已完成状态。

## 5. 产品已确认的交付边界

用户交付包只保留汇总表、`task_debug.json` 和发票/行程单 PDF；“申请单”指行程单。不再提供本机桌面输出模式，本机运行也只从页面下载 ZIP。缺失占位使用 `日期缺失`、`金额缺失`、`票面类型缺失`，金额缺失后不加“元”。文件拷贝、格式转换、JSON 写入时序及 ZIP 完整性检查由研发设计与实现。
