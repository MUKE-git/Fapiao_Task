# T3-4 OFD 处理与 PDF 转换规格（研发稿）

日期：2026-10-15。归属《计划分工》T3-4，对应最终图 P/S→SS→R。OFD 是输入凭证格式；用户交付仍按已确认的 T3-8 规则只给 PDF。解析、字段提取和版式转换是三个可分别成功或失败的环节，不以“ZIP 能打开”认定 OFD 已正确处理。

## 1. 文件登记与安全读取

- 公共附件链先分配 `file_seq` 并保留原名、邮件定位和真实格式。OFD 按受限容器打开，检查 `OFD.xml`、文档入口、页面索引及被引用资源；禁止容器路径穿越、符号链接逃逸、重复路径覆盖、异常压缩比或超出大小/页数/资源数限制。
- 加密、损坏、缺页、缺资源、未知版本分别记录；同封其他文件继续处理。OFD 中签章的存在不等于项目已验签，解析/转换也不能证明真伪。
- 单文件处理器返回与该 OFD `file_seq` 绑定的 `DocumentResult`；保存字段原值、规范值、来源于自定义数据还是具体页面的证据。不得由 OFD 处理器直接写 Excel 或决定跨格式同票关系。

## 2. 字段提取顺序与样本边界

先读 OFD 结构中的可用自定义数据，再读页面文字与位置；两者用于互相核对。自定义数据缺项可从可见页面补，若两处明确相反则记录冲突并待核，不静默择一。页面只有图片或文字无可靠阅读顺序时，调用 T3-2 多模态作为候选，并继续本地格式校验。发票与行程单角色按实际内容判断，不能只凭 `.ofd` 后缀。

| 目标字段 | A 样本已见证据 | 处理要求 |
|---|---|---|
| 发票号码 | `OFD.xml` 自定义数据及页面显示 `26447000000342589935` | 自定义数据与页面一致才可作为强证据；号码按 20 位数字规则校验。 |
| 开票日期 | 自定义数据 `2026年04月27日`，页面同日 | 转为 `2026-04-27`；不能用文件修改时间。 |
| 报销金额 | 页面价税合计 `121.74`；自定义数据另有未税合计 `118.19`、税额 `3.55` | 必须取价税合计，不能把名为“合计金额”的未税值直接当报销金额；以 `Decimal` 处理。 |
| 发票类型、票面类型、销售方 | 页面可见；结构数据并非全都有 | 按已确认字段规则规范化，保留页码/原文证据；票面类型不能从文件名猜。 |
| 出行时间、起终点 | A 样本无可确认的行程单值 | 留空，待真实行程单匹配后汇入。 |

上述只针对 A 样本和已核查的同票 PDF/XML；正文链接 C 组 OFD 已确认可打开并有同票页面字段，具体结构路径仍需研发在固定样本中核对。不同发行方模板可能变化，未知字段不可套用 A 样本位置猜值。

## 3. 转换成可交付 PDF

转换与提取分开执行并分别记状态。优先使用可在目标部署环境稳定运行的本地转换器；研发可先验证 [OFDRW 的 OFD 导出模块](https://github.com/ofdrw/ofdrw/blob/master/ofdrw-converter/doc/EXPORTER.md) 等方案。其项目文档明确提示 PDF 导出可能与 OFD 版式不一致，因此选型必须以 A/C 两组样本和其他签章、字体、跨页样本的实测结果为准，不能仅凭工具声明。若直接 PDF 导出效果不足，可评估先完整渲染每页再装配 PDF；这仍须核对图像清晰度、页数和票面完整性。

交付检查至少包括：PDF 文件头/解析成功、页数与源 OFD 一致、页面无空白或裁切、票号/日期/价税合计/销售方可见、签章和二维码所在区域未消失。自动检查可用文本和页面图像对照，人工审看代表性版式；自动检查不能证明完全等同或签章有效。转换失败或检查不过时保留已提取的发票字段与来源、标待核并触发 P08；不得把 `.ofd` 改名 `.pdf` 或把坏 PDF 放进用户 ZIP。

若同票另有可用的原始 PDF，T3-8 交付时优先选择原始 PDF；OFD 仍参与字段核验但不重复导出。若仅有可用 OFD，转换出的 PDF 是该 OFD 的**交付副本**，T3-4 向 T3-8 提供经检查的转换件与来源关系，T3-8 填写 `exported_name`；不声称它是原厂签发的原始 PDF。原 OFD 和转换过程文件不进入用户下载包。

## 4. 与主流程和异常提示的衔接

- 有 XML 的同票 OFD 交给 T3-6 进行来源合并，XML 有效结构字段优先，OFD 对空字段补证和冲突核查；仅 OFD 也可形成发票候选。未能确认同票不得按附件顺序合并。
- OFD 识别为行程单时，形成并保存行程单四字段；是否与 a 类发票匹配仍由既有行程单匹配器决定。
- 字段提取失败与 PDF 转换失败分开记录和展示：前者不能产生可靠字段，后者可能已有字段但无可交付 PDF。加密/损坏/工具不支持也须分因；P08 按实际环节填充。
- 候选进入统一的票号去重、字段校验和 Excel 筛选；转换成 PDF 不增加第二张发票记录。

## 5. 研发交接与验证材料

固定 A/C 样本及至少一份多页/签章/字体变体，提交容器结构、字段证据、转换 PDF 的页数与关键区域对照、部署环境依赖清单。分别展示“字段成功+转换成功”“字段成功+转换失败”“结构损坏”“加密/不支持”“同票已有 PDF”“异票冲突”的 `DocumentResult`、JSON、下载包和 P08/P13/P14 提示结果。解析器和转换器的单独通过不等于主流程已通过，真实部署环境必须再联调。
