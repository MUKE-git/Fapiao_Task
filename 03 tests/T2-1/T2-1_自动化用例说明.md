# T2-1 自动化用例说明

本文件说明技术用例如何落实[测试设计](T2-1_测试设计.md)。输入均为合成邮件、ZIP 或受控接口返回值，不使用用户保留的真实邮件。`scripts/test_t2_1_acceptance.py` 是断言实现；运行 `python -B "03 tests/T2-1/scripts/run_t2_1_acceptance.py"` 后产生 `result/latest.json`、`latest.md` 与原始日志。

**观察原理**：可直接读取的结果（`stats`、`MailRecord`、`task_debug.json`、Excel、落盘文件）直接检查。没有独立输出的调用（例如 PDF 处理器、XML/OFD/图片处理函数、IMAP FETCH）由测试在现有接口放记录调用的受控函数或模拟连接，再检查函数收到的输入及调用次数。这些观察器只在测试中存在，不修改生产业务逻辑。受控 PDF 返回值只能证明主循环如何使用返回数据，不能证明真实 PDF 识别准确。

下表每一行均列出输入、被测对象、动作、观察点与断言。最后一列把代码断言翻译成业务含义；详细字段值见设计文件及测试源码。

| 用例 | 输入数据 | 被测对象与执行动作 | 观察点、断言及预期 | 业务语言 ↔ 代码语言 |
|---|---|---|---|---|
| B00-01 | IMAP 未读 UID 空集合 | `run_pipeline` 执行空轮次 | `stats.unseen_total=0`；JSON 空数组、无 Excel 行、无 FETCH | 没有未读邮件 ↔ SEARCH 空且不进入附件链 |
| B01-01 | UID1001，一张 PDF，受控发票结果 | `run_pipeline` 调用附件及 PDF 接口并写输出 | 一文件、一 b 类 record、一 Excel 行；来源 `01`；PDF 调用一次 | 一张票一笔 ↔ `records[0].record_id=Msg1-01`、八列表头 |
| B02-01 | 同邮件甲乙两 PDF，票号/金额不同 | `process_message` 逐文件调 PDF 接口 | 两次调用，两条记录，来源分别 `01/02`，两行 | 不合并不串票 ↔ 文件级 `DocumentResult` 对应各自 record |
| B02-02 | 第二张 PDF 票号 `Not Found` | `process_message` 组装两结果 | 两记录仍在，乙保持缺票号、不复制甲 | 一票缺值不污染另一票 ↔ 第二条 `InvoiceFields.invoice_number` 原样缺失 |
| B03-01 | 一张交通发票 PDF 加一张行程单 PDF | `process_message` 后执行 `_apply_matching` | 一发票行、一个行程单候选；预期 `matched_itinerary.file_seq=02` 并汇入时间 | 单对单成组 ↔ 发票 record 挂行程单来源；若失败保留文档/实现差异 |
| B04-01 | b 类 PDF 结果故意带伪旅行字段 | `process_message`、`_excel_rows`、`mail_to_dict` | b 类 Excel 旅行列空、JSON 不含旅行键 | 办公用品不需要行程 ↔ b 类字段归属不接受发票侧伪旅行值 |
| B14-01 | 票面类型“客运服务”，无行程单 | `process_message`、`_apply_matching` | `kind=a类`，记录保留、旅行字段无有效值、有待核提示 | 缺行程单需核对 ↔ 交通关键词命中且匹配缺席 |
| B14-02 | 仅把 B14-01 改成“客运服务费” | 同上 | 与 B14-01 同样判 a 类并待核 | “费”字容错 ↔ 子串关键词仍命中 |
| B05-01 | Invoice 结果缺票号 | `process_message` 组装 | 一条记录保留、票号为 `Not Found`、来源 `01` | 缺字段不丢票 ↔ 主循环不删除发票记录；正式待核判定归 T2-6 |
| B05-02 | 两张 PDF 分别缺金额、日期 | `process_message` 逐文件组装 | 两记录分别保留自身缺失值 | 缺值不跨票补齐 ↔ 两条 `InvoiceFields` 各自缺对应字段 |
| B06-01 | PDF 结果 `role=Unknown` | `process_message` 分流 | 文件登记存在、无 record、有类型待核提示 | 认不出的 PDF 不伪造发票 ↔ `files=1, records=0` |
| B06-02 | PDF 结果 Invoice 且 `AI_PARSE_ERROR` | `process_message` 接收错误 | 记录保留且人工待核，`error_reason` 和提示含错误 | 失败可追查 ↔ 文件级错误传到邮件及记录状态 |
| B07-01 | 仅 XML，无处理函数 | `process_message` 查 `document_handlers` | `file_type=XML`、无 record、有未提取提示 | XML 暂未提取 ↔ 登记后走缺席分支 |
| B07-02 | 仅 OFD，无处理函数 | 同上 | `file_type=OFD`、无 record、有提示 | OFD 暂未提取 ↔ OFD 分支缺席 |
| B07-03 | 仅 PNG，无处理函数 | 同上 | `file_type=图片`、无 record、有提示 | 图片暂未提取 ↔ 图片分支缺席 |
| B07-04 | 仅 TXT，无处理函数 | 同上 | `file_type=其他`、无 record、有提示 | 其他文件不能静默丢弃 ↔ “其他”登记待核 |
| B07-05 | XML/OFD/PNG 各一个，三种受控函数 | `process_message` 按类型调用现有端口 | 三函数各一次，各收自己的类型和序号 `01/02/03` | 正确触发接口 ↔ `document_handlers[file_type]` 不交叉；不证明提取成功 |
| B08-01 | PDF+XML，PDF 返回发票，XML 脚本缺席 | `process_message` 双分流 | 两文件、一条 PDF record、一行；XML 提示待核 | PDF 照常入表、XML 留待后续 ↔ PDF 来源 `01`，XML 来源 `02` 被登记 |
| B09-01 | 相关主题、无附件 | `process_message` 收空附件集 | 无文件/record，有“无有效附件”提示 | 空邮件不造票 ↔ 记录数零但邮件可定位 |
| B10-01 | 直接 PDF 与 ZIP 内同字节 PDF，另有不同 PDF | `collect_mail_files` 经 `process_message` | 仅 `01/02`，`dedup_skipped=1`，PDF 调两次，两记录 | 重复附件不重复报销 ↔ MD5 去重在同邮件内生效 |
| B11-01 | 正常 PDF 加损坏 ZIP | `collect_mail_files` 解包并继续 | 正常票仍一记录，ZIP 错误留痕 | 坏包不能污染好附件 ↔ `ZIP_EXTRACT_ERROR` 与正常 record 并存 |
| B11-02 | ZIP 内 `../逃逸.pdf` 和普通 PDF | `collect_mail_files` 解包 | 危险路径拒绝、不在输出根外落盘，普通 PDF 留下 | 不安全路径被拦截 ↔ `ZIP_UNSAFE_PATH`、仅正常文件登记 |
| B11-03 | 三层嵌套 ZIP，另有正常 PDF | `collect_mail_files` 递归 | 第三层拒绝、正常 PDF 登记，记录深度错误 | 超深 ZIP 不进入处理 ↔ `ZIP_DEPTH_LIMIT` |
| B11-04 | 50/51 文件、15MB/15MB+1 字节四个边界 | `collect_mail_files` 分别处理四份 ZIP | 边界内保留；越界有错误且超限项不登记 | 数量/体积上限 ↔ `files` 数和 `error_reason` 与输入边界对应 |
| B12-01 | 两封无关主题未读邮件 | `run_pipeline` 只取邮件头 | 未读2、跳过2、相关0；无完整 FETCH、无 Excel | 有未读不等于有发票 ↔ 主题筛选挡住附件链 |
| B12-02 | 一封无关、一封相关且有 PDF | `run_pipeline` 筛选两邮件 | 未读2、跳过1、相关1；只相关 UID 入 JSON | 无关附件不混入报销 ↔ 完整 FETCH 仅相关 UID |
| B13-01 | 三封相关邮件，第二封首次完整 FETCH 断线后成功 | `run_pipeline` 重连按 UID 继续 | UID201/202/203 各一记录；第二封两次完整 FETCH；三行 | 中途断线不重做第一封、不漏第三封 ↔ UID 与 `Msg1/2/3` 一一对应 |
| B13-02 | 一张发票，Excel 写入器返回占用错误 | `run_pipeline` 接收写入错误 | JSON 留错误，日志不说写入成功，无 Excel 文件 | 表格写失败可追查 ↔ `EXCEL_PERMISSION_DENIED` 传播 |
| B13-03 | 三封相关邮件，第二封全部重试失败 | `run_pipeline` 处理最终异常 | JSON 仅保留第一封；`imap_error` 非空；第三封无 FETCH、无 Excel | 整轮未完成不得报成功 ↔ 错误和部分处理状态可区分 |

## 证据及结论口径

- **通过**：本行断言在实际运行中全部满足；不扩张到被替身隔离的能力。
- **失败**：执行了测试，但实际值与预期不同；原始堆栈、观察值与调用记录留在执行结果中。
- **未执行**：所需环境或样本未提供，例如真实邮箱与真实 PDF 的端到端/识别测试。
- **无法验证**：相关算法尚未接入，例如 T2-6 正式缺字段校验和 T3 跨格式匹配；接口调用通过不能替代这些算法的验收。
