## 3. T2-2 要交付的理解：数据模型长什么样

目标结构以《重构方案.md》§3 为权威。这里只讲"你必须想通的本质"，不堆字段表：

### 3.1 记录单位 = 一发票一笔

一封邮件**可以含多张发票**，每张发票各自成为一条记录。**不是"一邮件一笔"。** 想通它，你自然会知道一封多发票邮件该拆成几行。

### 3.2 行级来源（溯源到行）

每条记录都要能反问："这段话/这个字段从哪封邮件、哪个文件、谁提取(采用来源)来的？" 这是为**人工待核定位**服务的——出问题能一路追到原始凭证。

### 3.3 五类对象与它们的关系

- **来源元数据**：定位/溯源信息。
- **预读PDF**：处理前先抓文件类型、票号、金额（预读）。
- **a类发票 / b类发票**：交通类(需行程单) vs 非交通类。
- **行程单**：单独持有 出行时间/出发地目的地。

关系上：**行程单不单独成行**；匹配成功后把 `出行时间/出发地目的地` **汇入对应的 a 类发票行**。方向永远是 **行程单 → a 类发票**。

### 3.4 字段归属 = 校验边界

- b 类：只校验 6 个业务字段，**不碰/不校验** 出行时间/出发地。
- a 类：校验 8 个字段，其中 `出行时间/出发地目的地` 校验的是\*\*"是否已从行程单汇入"\*\*，不是"发票自身有没有"。

理解这个，你才不会把 b 类假报成"缺旅行字段"——这是本次特意消除的旧问题。

## 4. 关键决策与不变量（为什么这么定、不许违背什么）

| 决策                  | 为什么                                                          | 不许违背                             |
| ------------------- | ------------------------------------------------------------ | -------------------------------- |
| 一发票一笔(D1)           | 报销按发票逐张对，多发票要逐行                                              | 不要把一邮件合并成一行                      |
| 行级来源(D2)            | 异常时能追到原始凭证                                                   | 不要丢掉 邮件/文件/采用来源 任一维度             |
| 匹配=金额→原文件名，去销售方(D3) | 销售方同开票方多，配对不可靠                                               | **不要用销售方做自动配对**                  |
| "费"字容错(D4)          | 哈啰开"客运服务"、嗖嗖开"客运服务费"，是同一类；在票面类型中，“x费”和“x"代表同一个意思，无需补全，如实记录即可 | 不要全等匹配导致漏判 a 类                   |
| 字段归属=校验边界(D5)       | 消除 b 类假报缺字段                                                  | b 类 `出行时间/出发地` 必须留空，别填 Not Found |
| 匹配方式保留(D6)          | 溯源到用哪种规则配对                                                   | 不要删配对规则记录                        |
| 特殊版式票号在监制章内(D7)     | 纯正则抓不到票号，需预读/多模态兜底                                           | 抓不到时标 Not Found，**不要判废整条**       |
| 校验表列 ≠ 用户列(D8)      | 内部列只供评审；用户只见业务列                                              | 用户 Excel 不外泄内部列                  |

> 这些不只是"规则清单"，是**你判断未知情形的依据**。遇到文档没覆盖的异常，先回到"哪条不变量被破坏了"来判读，而不是猜。
