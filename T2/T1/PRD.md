# 发票邮件处理系统 PRD

> 本文档由代码反推生成,用于检证对原项目的理解,为后续重构铺垫。

## 一、产品背景与目标

### 1.1 背景
企业报销场景中,员工通过邮件接收电子发票与行程单(如网约车、出租车行程单 + 增值税电子普通发票)。财务/报销人员需逐封打开邮件、下载附件、肉眼识别字段、手动誊抄到报销表,流程重复、易错、耗时。

### 1.2 目标
自动化「收邮件 → 取附件 → 识别字段 → 汇总成表」的全流程,减少人工录入,同时保留人工核查兜底,保证数据可追溯。

### 1.3 非目标
- 不做邮件已读/未读状态管理(不自动标已读)
- 不做发票真伪校验
- 不做报销审批流程
- 不长期存储邮件内容(云端运行结束即清理)

## 二、用户角色与场景

| 角色 | 场景 |
|------|------|
| 报销人员 / 财务 | 本机运行,批量处理自己的发票邮件,生成桌面汇总表 |
| 演示 / 评审 | Streamlit Cloud 在线 Demo,填邮箱跑一轮并下载 zip |
| 开发 / 排障 | 查看 task_debug.json 与 agent 日志定位 AI 或附件问题 |

## 三、核心功能需求(用户故事)

### US-1 邮箱登录与收件
- 作为报销人员,我希望填入邮箱账号、授权码并选择 IMAP 服务器(支持 163/QQ/126/Yeah/Gmail/Outlook/自定义),以便程序能连上我的邮箱收件箱。
- 网易邮箱(163/126/yeah)需自动发送兼容的 IMAP ID 指令,QQ 等其他邮箱不发,避免登录失败。
- 登录失败时给出中文原因提示(账号/授权码错误、地址无法解析、SSL 异常、超时等)。

### US-2 未读邮件筛选
- 程序只处理 **IMAP INBOX 未读邮件**,不自动标已读(避免误改邮箱状态)。
- 仅处理主题含「发票 / 报销 / 报销凭证 / 电子发票 / 开票」关键词的邮件,其余整封跳过。
- 无未读邮件或无关键词邮件时,前端明确提示原因,并展示服务器侧 INBOX 邮件总数 / 未读数,便于和网页邮箱对照。

### US-3 附件提取
- 支持 **PDF 直接附件** 与 **ZIP 压缩附件**(仅解压根目录单层 PDF,跳过子目录)。
- 同一封邮件内按 **MD5 去重**:直接附件与 ZIP 内重复 PDF 只保留一份,避免重复入库。
- 附件名含 Windows 非法字符或乱码时,清洗为安全文件名,过短/乱码改成 `Attachment_{idx}.pdf`。

### US-4 文档类型三层判定
- 类型(Invoice 发票 / Itinerary 行程单 / Unknown)按三层依据判定,优先级 **附件原名 > AI 分类 > PDF 正文关键词**。
- 仅当三种依据规范化后 **不完全一致** 时,文件名加后缀「(待人工核查)」,一致时不加。
- 若附件名含「行程单」关键词优先判为行程单(避免「通行费电子行程单」被误判为发票)。

### US-5 AI 结构化信息提取
- 调用阿里云百炼(DashScope,qwen-plus 模型)从发票/行程单文本中提取 8 个字段:
  报销金额、发票号码、开票日期、出行时间、发票类型、票面类型、销售方、出发地/目的地。
- 必须输出 file_classifications(每个文件对应 Invoice/Itinerary/Unknown)。
- 出行时间只取行程单 **第一笔行程** 的起始时间;出发地/目的地只取第一段。
- 金额只取「价税合计(小写)」,不带货币符号。

### US-6 兜底与重试
- AI 调用 HTTP 429/5xx 自动重试 2 次(间隔 1s/3s)。
- AI 不可用 / JSON 解析失败 / 缺字段时,用本机正则兜底生成「伪结果」,关键字段缺失标记 FIELD_NOT_FOUND。
- 关键字段(发票号/日期/金额)缺失的邮件不计入 Excel 汇总表,但列入人工复查清单。

### US-7 输出与汇总
- 生成「发票信息汇总表.xlsx」,列顺序固定:发票日期、发票号码、报销金额、发票类型、票面类型、出行时间、销售方、出发地/目的地。
- 已存在时追加行(不覆盖),表头缺失时补写。
- 生成 task_debug.json:每封邮件的文件、AI 结果、分类不一致、错误原因等结构化快照。

### US-8 文件重命名规则
- 发票:`{票面类型}+{开票日期}+{金额}元.pdf`
- 行程单:`行程单+{出行日期}+{金额}元.pdf`
- 未知:`票据+{开票日期}+{金额}元.pdf`
- 三层不一致时追加「(待人工核查)」;同名文件自动加 (1)(2) 避免覆盖。

### US-9 人工核查提示
- 前端列出三类待办:
  1. 三层类型不一致(含「待人工核查」后缀的文件)
  2. AI 分类与本机分类不一致的附件
  3. 关键字段缺失 / AI 异常 / 交通类发票缺行程单 的邮件(附主题与 Date 头时间便于定位)
- 交通类票面类型(客运服务费/通行费/网约车服务费等)若无行程单附件,强制提示。

### US-10 部署模式适配
- **本机模式**:结果写入用户桌面下指定子文件夹(默认 Invoice_Task),支持 zip 下载备份。
- **云端模式**(Streamlit Community Cloud 或环境变量强制):自动用临时目录,处理完打包 zip 下载,服务器不留存。
- 页面与日志不展示百炼 API Key。

## 四、业务流程

```
登录邮箱(IMAP SSL)
   ↓
SELECT INBOX + SEARCH UNSEEN
   ↓
逐封未读邮件:取 SUBJECT/DATE 头
   ↓
主题含发票关键词? ─ 否 → 跳过
   ↓ 是
拉取整封 MIME,遍历附件
   ↓
PDF 直接落盘 / ZIP 解压单层 PDF  → MD5 去重
   ↓
pdfplumber 抽正文 + 本机关键词预分类(Invoice/Itinerary/Unknown)
   ↓
合并:附件原名优先 > 正文分类  → identified_type
   ↓
调用百炼 qwen-plus(system+user)→ JSON
   ↓ (失败走正则兜底)
按「原名>AI>正文」确定重命名类型,三层不一致加「待人工核查」
   ↓
重命名 PDF + 收集不一致列表 + 收集人工复查项
   ↓
关键字段齐全 → 追加到 Excel rows
   ↓
所有邮件处理完 → 写汇总表 xlsx + task_debug.json
   ↓
本机:保留桌面目录;云端:打包 zip 下载并清理临时目录
```

## 五、非功能需求

| 维度 | 要求 |
|------|------|
| 邮箱兼容 | 163/QQ/126/Yeah/Gmail/Outlook + 自定义;网易需 IMAP ID |
| 部署 | 本机桌面输出 + Streamlit Cloud 临时目录双模式 |
| 安全 | API Key 不在页面/日志展示;走环境变量或 .streamlit/secrets.toml |
| 可追溯 | task_debug.json 全量快照 + debug-{run_id}.log agent 日志 |
| 容错 | AI 重试 + 正则兜底;IMAP 异常中文提示;Excel 占用提示关闭重试 |
| 幂等 | 不自动标已读;同输出文件夹多次运行会累积(需用户用新文件夹或手动标已读) |

## 六、当前技术栈(重构参考)

- 语言:Python 3(带 `from __future__ import annotations`)
- 界面:Streamlit
- 邮件:imaplib(IMAP4_SSL)

## 八、待重构关注点(待讨论)

1. `invoice_pipeline.py` 单文件 1300+ 行,函数职责较多,可按「配置/工具/邮件/PDF/AI/Excel/主流程」拆分模块。
2. RunConfig、AI 调用、Excel 写入、重命名逻辑耦合在主流程内,可抽象为独立类/服务便于测试。
3. agent 日志(#region/#endregion)与业务逻辑混排,可抽离为独立 logger。
4. 兜底正则与 AI prompt 规则可外置为配置,降低维护成本。
5. 前端错误展示与后端 stats 字段强耦合,可定义清晰的结果契约。
