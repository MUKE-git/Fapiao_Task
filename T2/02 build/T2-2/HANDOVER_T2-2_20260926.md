## 2. 已冻结的数据关系

- 一封邮件对应多个文件。
- 一个 `Invoice` 文件必须且只能对应一条 `record`。
- 一条 `record` 通过 `source.source_file_seq` 指向其发票来源文件。
- 行程单不作为用户表中的独立发票行。
- 单发票、单行程单场景可以建立 `matched_itinerary` 关系；旧 JSON 不存在的 `match_amount` 保持为空。
- 多发票邮件若旧 JSON 只有一组邮件级 `audit_result`：第一张发票承接已有字段，其余发票记录留空并标记“人工待核”。
- 没有发票候选文件的邮件不伪造 record。
- 旧数据没有的字段保留结构并留空，不从 PDF、`text_snapshot`、正则或 AI 补取。

## 3. 转换脚本边界与使用方法

`convert_task_debug_v2.py` 只做旧 JSON 到新结构的映射：

- 只读取旧 JSON 中已存在的显式字段；
- 不读取原始 PDF；
- 不解析 `text_snapshot`；
- 不调用 AI；
- 不调用兜底正则提取新数据；
- 不把发票金额复制成行程单匹配金额；
- 不虚构承运方、预读票号或预读金额。

脚本开头的 `OLD_DEFAULT` 是默认输入文件。修改默认来源时必须保留原始字符串前缀 `r`，并填写具体 JSON 文件：

```python
OLD_DEFAULT = r"C:\Users\lenovo\Desktop\T1-3\task_debug.json"
```

运行方式：

```powershell
python -B .\convert_task_debug_v2.py
```

`-B` 用于避免生成或更新 `__pycache__`。

也可以显式指定输入和输出：

```powershell
python -B .\convert_task_debug_v2.py "旧JSON完整路径" "输出目录"
```

默认输出目录为项目根目录下的 `_v2_output`，包括：

- `task_debug_v2.json`
- `内部校验表.xlsx`
- `发票信息汇总表.xlsx`
