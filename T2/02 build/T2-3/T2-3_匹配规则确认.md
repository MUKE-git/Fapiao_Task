# T2-3 匹配规则确认

当前版本：2026-10-09。项目负责人已批准修订计划并授权开工；核对依据见 [修订计划与实施核对](T2-3_修订计划与实施核对_20261009.md)。2026-10-04旧版副本保存在 baseline/revision_20261009/。发票是主记录，行程单为补充附件；程序逐张 a 类发票寻找候选，一票最多关联一单，一单最多补充一票。

1. **原名尾缀**：`行程单A↔发票A`、`行程单B↔发票B` 可以对应，`行程单A↔发票C` 无尾缀对应关系。金额缺失或差值超过 0.5，仍可通过明确原名关系匹配。
2. **金额层级**：优先选择按精度舍入后相等的候选；该层不唯一再核对原名。只有没有相等候选时才进入原始差值 ≤0.5 的候选层。
3. **一对一冲突**：多张发票拟关联同一行程单时，仅一张发票的非空尾缀与该单明确对应，则优先确认它，其余发票进入下一轮；无或多张明确对应则冲突相关发票和行程单人工待核，停止其自动匹配，其他独立配对继续。
4. **末尾单对单**：确认配对后重新计算剩余候选；最后恰好一票一单直接成组，无须金额或名称支持，包括金额缺失、不同和空尾缀。只对来源有效的 a 类建立关联。

实现采用以下具体解释，并以用例验证，不新增模型字段：

- 每轮数量按全部尚未确认配对的发票/行程单计算。只有确认配对才各扣除一项；b类、未知类别、来源异常及不可解决冲突仍计数，不因过滤它们制造单对单。初始和末尾单对单都适用。
- 多数量组合：先选相等候选层，否则选容差候选层；该层只有一项则拟配对，多项用尾缀在该层内消歧。两金额层均无候选时，在邮件剩余可用行程单中按尾缀兜底。仍不唯一暂存为本轮未解决项，其他关系确认后下一轮可重算，结束时再待核。不选择“最近金额”，不使用最大匹配推断。
- 尾缀从完整解码原名去实际扩展名后，取最后一个对应角色词（发票/行程单）之后的文本。采用 Unicode NFKC、大小写统一、边缘空白/分隔符清理；保留尾缀内部字符。非空尾缀完全相等才形成名称候选；不模糊匹配、不按包含关系匹配，角色词之前的共同平台名称不作为证据。
- 名称不是唯一金额候选的额外否决条件；用户的 A/C 反例描述的是尾缀证据不成立。没有可识别角色词或尾缀为空时不猜名称关系，金额规则仍可工作。
- 每轮所有拟关联先计算完毕，再按目标行程单分组检查冲突。唯一明确尾缀优先只裁决已形成的拟关联，不越过金额层选择其他单。统一裁决后统一确认，从工作候选移除确认关系，已确认关系不再分配；原始列表不删除。没有新增配对时结束，不按附件顺序猜剩余关系。
- 持久化 itineraries 是行程单字段的事实来源；传入 DocumentResult 用于核对端口输入一致性。正式调用链中二者同时存在；不把提取结果临时复制成新的候选实体。
- 成功关系中的金额保留所选行程单的原始精度；金额/旅行字段缺失仍可按数量或名称规则建立关系，同时保留或补充实际异常待核。不将其他阶段待核状态改成 complete。
- 匹配阶段失败原因写既有 error_reason，并返回现有提示字典；本次中间未命中/歧义延迟到结束，已有待核原因不清除。不增加“匹配方法/置信度”字段，重复相同输入保持关系和原因稳定。
