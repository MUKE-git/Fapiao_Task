## 1. 交付与作用

根目录新增 `itinerary_matcher.py::match_itineraries(mail, itineraries) -> list[dict]`。现有 `stage_ports.load_stage_ports()` 自动加载，`pipeline._apply_matching()` 按邮件调用，无需修改调度、模型或处理器接口。

此前发票与行程单只形成候选，匹配器缺席时无法汇入旅行字段。现在同邮件一票一单自动成组；复杂组合按 Decimal 相等层、原始差值 ≤0.5 层、原名尾缀核对，明确名称可兜底缺失或超容差金额。一单被多票竞争时全部撤回相关拟配对，独立配对继续。只有 a 类写 matched_itinerary 和旅行字段；全部行程单保留，用户 Excel 不增行程单行。

规则答复及实现解释见 [T2-3_匹配规则确认.md](T2-3_匹配规则确认.md)，完整阅读分析与验证计划见 [T2-3_阶段分析与详细计划.md](T2-3_阶段分析与详细计划.md)。覆盖 CF-003、CF-016，并验证 CF-006/015 相关的完整行程单与原名使用。

## 2. 关键实现及例子

引擎先按邮件全部发票、全部行程单的原始数量判断例外。复杂组合从同邮件候选中优先选择按低精度 ROUND_HALF_UP 后相等项；无相等项才用原始差值容差层。当前层唯一即可拟配对，多个候选按尾缀在该层内消歧；两金额层均为空时，在全部可用行程单内找明确尾缀。仍不能唯一确定则待核，不按最近金额或最大匹配猜测。

| 场景 | 实际规则与结果 |
|---|---|
| 一张 a 类发票100.00 + 一单900.00，名字不对应 | 单对单例外成组，match_amount 保留900.00 |
| 多数量：发票100.00，行程单100.0000及100.40 | 选择相等层100.0000，容差项不与其并列 |
| 多数量：发票100.00，两个相等金额的 A/B 单，发票尾缀B | 用尾缀B确定对应项 |
| 多数量：发票A金额缺失、单A金额500.00 | 无金额候选，明确尾缀A可配对；金额缺失保留待核 |
| 多数量：发票C金额缺失、单A金额500.00 | 无金额/尾缀证据，不配对 |
| 两票争一单，另有一票一单独立对应 | 竞争两票均待核，独立一组完成 |

名称核对使用完整 decoded original_name；去实际扩展名后，取对应角色词最后一次出现之后的非空尾缀，进行 NFKC、大小写与边缘分隔符归一化，尾缀完全相等才算证据。不读取内部/导出名，不模糊匹配。当前支持用户明确的“发票A/行程单A”形式；角色词之前的标识或英语 Invoice/Itinerary 名称没有额外猜测算法。

数据事实来自 `mail.itineraries`；非空 `DocumentResult` 入参用于核对同文件金额和旅行字段的一致性。直接调用者可传空结果列表处理已完整持久化的 MailRecord。匹配不修改行程单、原始金额、文件名或发票业务字段，也不把行程单序号加入发票来源序号列表；关系专用字段指向行程单来源。

引擎原位重算匹配所属字段，清除本次调用前的旅行关系，保持结果确定性。失败、竞争、剩余行程单及已配对但实际字段缺失的原因写入既有 error_reason，返回兼容提示；原因带记录号，提示带邮件主题、规范化时间、文件序号和原名。重复调用相同输入保持 JSON 原因稳定。已有人工待核状态不改为 complete。邮件原始 Date 头不在端口输入中，提示的 mail_date_header 留空，已有主干提示仍保留其原始头。
