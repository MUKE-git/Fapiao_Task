## 2. 已核对的实现与缺口

| 链路 | 当前事实 | T2-5 所需工作 |
|---|---|---|
| 邮件标识 | `pipeline.py` 用 IMAP UID 抓取未读邮件，按搜索顺序赋 `MsgN` 并写入 `MailRecord.mail_uid`。 | 保持现有编号；专项核对不同邮件、跳过主题邮件及输出 JSON 的 UID 对应。 |
| 文件编号和去重 | `attachment_processor.py::collect_mail_files` 对直接附件与 ZIP 内容共用 `files[]` 序号，邮件内 MD5 相同内容只保留首份；保留件落盘。 | 验证 01–99、跨形态顺序、重复项不占新序号和落盘字节与 JSON 的关系。 |
| 原名与内部名 | `original_name`、`internal_name` 已入 JSON；当前安全名先截到 180 字符，之后才加 `MsgN_序号_` 与冲突后缀。`utils.clean_filename` 的旧兜底还可能把非 PDF 后缀改成 `.pdf`。 | 保留完整 MIME 解码原名；仅存盘名清理非法/空/不可用字符；完整实际内部名 ≤120 字符，计入前缀、扩展名及重名后缀；超长主体截断加短摘要，保留实际扩展名。ZIP 容器实际落盘名同样不应超过上限，但容器不占 `files[]` 序号。 |
| 记录来源 | 主流程生成 `record_id=mail_id-file_seq`，发票保存 `source_file_seq`，匹配行程单保存其 `file_seq`；输出前已有序号存在性检查。 | 补齐反查检查：文件序号与内部名唯一、内部名对应本轮实际文件、记录编号不重复、发票和行程单引用同封登记文件且类型一致；JSON 与文件可按两方向核对。 |
| 输出目录 | 本地默认固定目录；临时模式每次单独创建根目录。 | 按本轮用户决定，T2-5 不改本地目录行为；测试在彼此独立的临时目录执行。 |

注意：T2-3 匹配使用完整 `original_name`，T2-4 仲裁按 `internal_name` 复读来源 PDF。本阶段不得用截断后的存盘名覆盖原名，也不得改变仲裁对来源文件的访问路径。

## 3. 实施顺序

1. **保存基线。** 记录当前 Git 状态、相关源码摘要和 T2-1～4 现有研发测试结果；保留工作区已有的 T2-4/T3 未提交成果，不清理、不覆盖。
2. **完善附件命名。** 在 `attachment_processor.py` 内实现唯一的内部存盘名生成与冲突处理，先计算 `MsgN_序号_`、扩展名、重名后缀所占长度，再裁剪主体并加稳定短摘要；保留文件类型与完整原名。对 Windows 非法字符、结尾空格/点、保留设备名及空名采用安全存盘名。直接附件、ZIP 内文件与落盘 ZIP 容器共用同一长度口径；不改变文件编号来源。
3. **加强来源链检查。** 在 `pipeline.py` 输出 JSON/Excel 前核对邮件编号/UID、文件序号、内部名、实际文件路径、发票记录与行程单关系；从 JSON 的 `files[]` 可找到真实文件，从文件名可在同一轮 JSON 中唯一找到邮件、UID 和相关记录。无业务记录的“其他”文件允许只反查到邮件及文件登记，不伪造发票。
4. **研发专项自测。** 在 `02 build/T2-5/` 编写受控测试，标准预期独立于实际输出：直接附件/ZIP 混排、同内容去重、同名不同内容、MIME 编码名、非 PDF 与空/非法/超长中文名、120 字符边界和冲突后缀；两封邮件同序号但 UID 不同；发票/行程单正反查；来源链断裂、缺失或越界落盘名应被发现。测试落盘文件字节、JSON 约定字段及路径；不调用真实邮箱或在线 AI。
5. **回归与交接。** 复跑 T2-1～4 研发测试及适用的现有固定用例，不改其冻结预期；记录命令、通过数、差异和限制。写 T2-5 研发交接，明确已实现、已运行、未验证和需测试工程师独立验收的内容。独立验收资料应由测试侧置于 `03 tests/T2-5/`，不以研发自测冒充。

## 4. 研发完成判据

- 同一轮内 `MsgN-序号` 唯一；相同文件内容在同一邮件只保留首份，跳过项记录原因；不同邮件可各有 `01`，但 UID 与 `mail_id` 能区分。
- JSON 的完整原名与输入解码结果一致；内部实际文件名全部 ≤120 字符，扩展名与实际文件形态一致，同名不覆盖、超长名有短摘要。业务导出名保持 T3-1 前的空值。
- 每个 `files[]` 均能定位本轮实际落盘文件；每个实际保留文件能唯一反查 `files[]`、邮件编号与 UID。每个发票/行程单记录能反查同邮件来源文件；坏引用在写出前被发现。
- 研发测试与受影响回归执行结果有可复现证据；报告区分合成输入、受控处理器、实际文件读写与尚未验证的真实邮箱/在线 AI/测试侧独立验收。
