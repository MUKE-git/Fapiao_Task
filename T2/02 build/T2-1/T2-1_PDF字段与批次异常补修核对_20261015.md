# T2-1 PDF 字段与批次异常补修核对

日期：2026-10-15。依据为 `01 docs/02 technical-design/字段表.txt` 与 `01 docs/01 project/重构方案.md` §3.1 实体关系图、§3.2 Excel 视图。本文记录本次研发补修与受控验证，不代表真实邮箱或在线百炼联调通过，也不修改冻结用例的顺序和预期。

## 字段流逐项核对

| 实体 | 约定字段 | 当前来源与内部保存 | 用户 Excel |
| --- | --- | --- | --- |
| 邮件 | `mail_id`、`mail_uid`、`subject`、`mail_date` | 主循环取 IMAP UID、Subject、Date；每封作为一个 JSON 邮件对象。失败邮件也保留已取得的 UID、主题、日期及错误原因 | 不写 |
| 文件 | `file_seq`、`file_type`、`original_name`、`pre_read_type`、`pre_read_invoice_no`、`pre_read_amount`、`internal_name`、`exported_name` | 附件收集器编号、登记格式和原名；PDF 预读角色、票号与金额。本次补修使行程单的 `pre_read_amount` 取本单金额；`exported_name` 仍待 T3-1 实际交付时填写 | 不写 |
| 发票 | `record_id`、`kind`、日期、号码、`total_amount`、发票类型、票面类型、销售方、`status` | `record_id` 由程序分配；六个业务字段由同张发票 PDF 的模型候选或本地兜底取得，映射到 `records[].fields`；T2-6 校验状态 | 一张发票一行；六个发票业务字段 |
| 行程单 | `record_id`、`match_amount`、`travel_time`、`origin_dest` | `record_id` 由程序分配；其余三个字段从当前行程单 PDF 提取，写入 `itineraries[]`，包括未匹配项。本次补修模型提示词、角色字段检查及本地兜底的 `match_amount` | 不单独成行；仅匹配到 a 类发票后汇入时间、起终点两列 |
| 匹配关系 | `matched_itinerary.file_seq`、`matched_itinerary.match_amount` | T2-3 确认关系后，引用已保存的行程单文件序号和其原始金额；不把发票价税合计写成行程单金额 | 不加行程单金额列 |

结论：对照四实体全部约定业务字段，已发现并补上行程单 `match_amount` 的实际提取缺口，同时修正行程单预读金额和模型按角色检查字段的遗漏。组装层继续兼容 T2-2 已确认的同一行程单旧结果 `total_amount`，但不会借用另一张发票的金额；新 PDF 提取已明确把两种金额分开。现有发票六字段、行程单时间/起终点、内部编号及 JSON 关系均有提取或程序赋值入口。本次没有证明模型在任意真实票面上取值正确；扫描 PDF/OCR、XML、OFD、图片、链接及证据级模型校验仍按既定 T3 边界推进。票面类型有效清单仍待单独确定。

## 批次异常处理

- 单个 PDF/文件处理器抛出异常：保留该文件登记和原因，继续处理同邮件其他文件；该邮件列入 `stats.failed_mails`，最终 JSON 留错误信息，其余可处理发票仍参与本轮匹配、去重、校验和 Excel 写出。
- 一封邮件的抓取或组装抛出异常：保存已取得的 UID、主题、日期和已有内部记录，标记其中记录人工待核，继续下一封邮件。
- 邮件全部处理后的仲裁/校验等意外异常：不生成未经完成后处理的 Excel；已有记录以人工待核状态写入部分 JSON，并通过 `stats.run_error` 明示。页面提供“部分结果供核对”下载，不能显示完整成功。
- Excel 写入失败通过 `stats.excel_error` 和页面错误提示暴露；JSON 仍保存。页面不把失败批次显示为完整成功。

## 真实百炼在线冒烟（同日补充）

用户要求控制费用，仅用已审核的 C05/v1 一张发票和一张行程单验证在线 AI。`online_smoke_c05.py` 调用现有 `pdf_processor.process_pdf`，读取项目已有的百炼配置，限制最多 2 次真实 `Generation.call`，不连接真实邮箱，不跑其余用例。首次在隔离网络中尝试请求时，DNS 解析失败，未取得模型响应，字段来自本地兜底；该结果**不计入在线通过**。随后在允许网络访问的环境中重跑，在线报告覆盖了该失败记录。

最终报告 `C05_真实AI在线冒烟_20261015.json`：配置模型 `qwen3.7-max`，实际请求 2 次，两次 HTTP 状态均为 200；发票和行程单角色均正确，`fallback_used=false`、`error_reason` 为空。发票日期、号码、价税合计、发票类型、票面类型、销售方 6 项，以及行程单独立金额、出行时间、起终点 3 项，均与 C05 已审核预期一致。报告保留预期、实际值和逐字段比较，不包含 API Key。为避免误触发收费，脚本必须显式带 `--run-once` 才执行。

这证明当前配置能对该组**合成文字型 PDF**完成真实百炼调用和文件级提取；并未验证真实邮箱接入、真实票面识别、其他用例、整轮 Excel/JSON 在线链路或正式验收。
