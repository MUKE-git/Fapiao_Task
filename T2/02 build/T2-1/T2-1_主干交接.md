## 阶段结论与交付文件

T2-1 已形成可运行的主干：只读获取 INBOX 未读邮件、按现行主题关键词筛选、统一收集附件、按物理格式调用处理器、将每张已识别 PDF 发票组装成独立记录，并输出业务 Excel 与可追源的 `task_debug.json`。此处的“已完成”指上述框架及本阶段输出行为；真实邮箱、真实 PDF 识别准确度仍需后续专门验证。

| 文件 | 本阶段交付职责 |
|---|---|
| `pipeline.py` | `run_pipeline(cfg, log) -> (mismatches, stats)` 入口；收件筛选、文件分流、结果组装、待核与输出调度 |
| `attachment_processor.py` | `collect_mail_files`：直接附件、ZIP 解压、MD5 去重、编号、安全存盘及文件类型登记 |
| `pdf_processor.py` | `process_pdf`：单个已登记 PDF 的预读及 AI/正则提取适配，不改正式文件的编号存盘名 |

| `stage_ports.py` | T2-3/4/6 及 T3 文件形态与凭证组合的接入点；缺席时由主循环标记待核 |
| `data_model.py`、`excel_writer.py` | 沿用冻结模型与写表接口，分别序列化来源关系、写入业务列 |

根目录 `app_demo.py` 调用新版 `pipeline.run_pipeline`；`invoice_pipeline.py` 保留兼容导入。T1-7 终版位于 `T1/`，本阶段未把它作为运行时模块导入。

## 调用链

`app_demo.py` → `pipeline.py::run_pipeline(cfg, log)` → `attachment_processor.py::collect_mail_files` → 各形态处理器 → T2 后续环节 → `excel_writer.py::append_to_summary_excel` 与 `data_model.py::mail_to_dict`。

当前 PDF 处理器为 `pdf_processor.py::process_pdf`，每次只接收一个已登记文件。它复用根目录已有的文本 AI/正则能力，但隔离旧接口的重命名副作用，不改正式凭证的编号存盘名。主流程不 import 或执行 `T1/` 下的文件。

## 职责边界

- `attachment_processor.py`：直接附件、ZIP、MD5、文件序号、安全存盘、格式登记；未知扩展名记为“其他”。不提取业务字段。
- `pdf_processor.py`：单文件预读与提取；返回 `processor_contracts.py::DocumentResult`，含 `file_seq`、角色、字段及异常；不收邮件、不写 Excel。
- `pipeline.py`：按格式调用、组织一发票一笔记录、保留来源、收集待核提示、调用后续阶段、组装业务 Excel 行和写调试 JSON；不实现 ZIP/PDF/匹配/仲裁算法。
- `stage_ports.py`：为 T2-3 建议模块 `itinerary_matcher.py::match_itineraries`、T2-4 建议模块 `dedup_arbitrator.py::arbitrate_records`、T2-6 建议模块 `field_validator.py::validate_records` 留接入点。文件尚不存在时明确标人工待核，不宣称这些任务已完成。T2-5 由附件登记、主循环和冻结数据模型共用同一编号链。
- T3 预留：建议模块 `xml_processor.py::process_xml`、`ofd_processor.py::process_ofd`、`image_processor.py::process_image`、`voucher_matcher.py::combine_vouchers`。这些是当前主流程采用的建议接入名，尚非冻结契约；对应任务实施时应核对接口。相应提取/配对尚未实现。未支持文件已登记并提示，不伪造发票记录。

## 来源与输出

每封邮件记录 `mail_id`、`mail_uid`、主题和 Date；每个保留文件有邮件内唯一 `file_seq`，存盘名以 `MsgN_序号_` 开头。每张已识别发票的 `record_id=mail_id-file_seq`，`source.source_file_seq` 指向已登记文件。输出前检查引用没有断链。行程单不独立写入用户 Excel；未来匹配成功后把来源序号和旅行字段汇入发票记录。Excel 只含八个业务列，来源关系保存在 `task_debug.json`。
